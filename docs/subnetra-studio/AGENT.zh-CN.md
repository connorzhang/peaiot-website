## 1. 软件定位
**Subnetra Studio** 是一个为 Subnetra Layer-3 自适应网络引擎提供健壮、零配置体验的编排与管理仪表板。它与纯 Zig 编写的网络二进制文件交互，并在 Linux 和 Windows 上编排复杂的网络拓扑（ZeroTier、NAT 路由）。

权威的发展方向见 `docs/ROADMAP.zh.md`。该文档是决定“做什么”的唯一真相来源；而本文件管理你“在开发时必须如何规范行为”。

## 2. 首要指令
**绝不偏离目标和安全边界。永远不要。**
你必须严格按照 Roadmap 描述构建系统——不多也不少。范围蔓延 (Scope creep)、静默重新设计以及未经请求的代码重构都是失败的表现。

## 3. 不可谈判的铁律
违反以下任何一条都是严重事故：

1. **凭证零泄露**：绝对禁止将 `.env`、`config.json`、`*_config.json`、SSH 密钥以及任何真实的 IP/PSK 提交到 Git。`.gitignore` 必须全局拦截它们。如果测试需要模拟凭证，必须使用明显的占位符（例如 `x.x.x.x`、`mock_psk_123`）。
2. **构建目录纪律**：Rust 的 `target/` 和构建的 `output/` 目录必须严格保留在 `.gitignore` 中。绝对禁止将二进制文件推送到代码库中。
3. **终端可见性与命令执行**：绝对禁止在系统调用中使用 `blocking: true`。所有的终端命令必须强制使用 `blocking: false` 和 `requires_approval: false`，确保命令在可见的终端面板中执行，让人类用户可以实时监控日志、进度和速度。严禁导致 UI 卡死或状态不可知的后台静默执行。
4. **安全全局检索**：绝对禁止使用原生的 Shell 命令（如 `Get-ChildItem`、`find`）进行全文或敏感词搜索。你必须且只能调用系统内置的 `Grep` 工具，以强制继承 `.gitignore` 的排除规则，彻底杜绝因扫描构建产物导致系统卡死。
5. **禁止擅自篡改环境**：除非 `load-dev-env` 硬件指纹规则明确允许，否则绝对不要尝试猜测或自动安装操作系统级别的工具链（如 `rustup` 或 `zig`）。
6. **双语文档**：所有架构文档和本 `AGENT.md` 必须同时维护英文（root/docs）和中文（`*.zh.md` / `*.zh-CN.md`）版本。代码注释和提交信息默认使用英文。

## 4. 你的工作方式
- **仅进行精确的、符合目标的修改**：不要进行无关的重构，不要提交满篇格式化的代码。
- **声明完成前必须验证**：在结束任务前，永远要运行构建/测试或验证脚本输出。
- **边界检查**：在任何主要功能或里程碑结束时，必须主动执行一次“全局越界评审”（Global Out-of-Bounds Review），以确保代码库没有偏离 Roadmap。

## 5. 本文件的同步规则
**每当编辑 `AGENT.md` 时，必须在同一提交中更新 `docs/AGENT.zh-CN.md`，使两者保持语义上的一致。** 它们是两种语言的同一份契约。
